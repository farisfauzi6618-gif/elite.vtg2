# Customer payment recovery

- An unpaid normal invoice remains recoverable for seven days from its original creation, not seven days from every reopen. Standalone catalog selections retain their 24-hour lifetime.
- Explicit authenticated member resume or a verified guest payment link rechecks published/active inventory, available quantities including Reserve holds, sale/current prices, and release schedules. Only the saved selection belonging to that still-unpaid invoice is refreshed within the invoice lifetime. Saved recipient, totals, rewards, protection, shipping and stock are not repriced or changed by resume.
- Guest payment offers an optional **Salin tautan pembayaran** action before proof submission. It requests a link only when tapped. Clipboard denial falls back to a selectable URL. No new account, database table, Blob object, background job or polling is added.
- A purpose-scoped HMAC-SHA256 capability uses the existing server CONFIG_SECRET. It binds the guest invoice ID and original creation timestamp. The token stays in the URL fragment and is exchanged through a same-origin, rate-limited POST. Invoice ID/phone alone does not grant unpaid-payment access; the capability cannot log into a customer/admin account. Expired, cancelled, Reserve or member-associated invoices cannot use this guest capability.
- The capability can reopen the same guest invoice across browsers until expiry. After proof exists it returns a read-only tracking destination instead of reopening payment. Payment session rotation is guarded against concurrent changes. Tokens are not put in analytics, HTTP URLs or referrers, and the continuation page removes its fragment immediately. A transient exchange failure can retry using only in-memory input.
- Existing raw-cookie canonical-domain migration links remain supported separately. The new continuation accepts only the expected local payment/tracking destinations.
- Tracking GET and invoice/phone POST now share the same authorized response builder, so a first Reserve lookup includes status, remaining balance and deadline immediately.

Verification: real API integration fixtures cover invoice expiry, scope/ownership, cross-origin, token tampering, prices/stock/schedule/sale changes, original totals, post-proof tracking and first Reserve lookup. Browser QA covers local 320/390/1440 px layouts, clipboard fallback, retry after stripping the fragment, member and guest resume, and immediate Reserve settlement CTA. No fictional production transactions or actual messages are created for verification.
