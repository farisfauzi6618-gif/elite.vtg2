# ELITE.VTG — personal reward presentation

Catalog cards retain normal prices, typography and SOLD/size behavior. Logged-in accounts with currently active rewards get one dismissible quiet notice above search. Guests see normal prices; the existing optional account button is available on checkout too.

Product detail asks the server for a quote. `Your ELITE Price` is shown only for an orderable product with one consistent available variant price and an applicable percentage reward without a minimum-spend or discount cap. Fixed rewards, minimum-spend rules, caps, variable variant prices, SOLD and scheduled products receive only a benefit notice. No strike-through prices or sale badges are added.

Cart and checkout receive backend quotes through `/api/rewards/quote`. Product prices/category/stock come from the database, not client-submitted unit prices. Rules include personal owner, percentage/fixed, minimum cart subtotal, maximum discount, validity window, usage limits, product/category restrictions, first order and active status. Product and category restrictions intersect when both are set; only the eligible goods subtotal is discounted. Manual agreed-price orders retain owner verification; restrictions cannot be inferred for manual items, so restricted vouchers do not apply there.

When several rewards qualify, customers can select one in cart/checkout. The default `auto` chooses the greatest actual rupiah discount, with a stable voucher-ID tie break. No stacking. `none` opts out. Labels explicitly disclose automatic best-value choice. Minimum-spend progress is shown for available but inapplicable rewards. Checkout POST recalculates stock, schedule, pricing and rewards under its existing write transaction; frontend discount/money/owner fields cannot override them.

The original first-purchase 5% eligibility and `first_purchase_discounts` claims are reused as built-in reward `first-purchase-5`. The additive `release_0005_personal_rewards.sql` adds `purchase_vouchers`, `purchase_voucher_claims`, and nullable order voucher ID/label snapshot columns. No existing product/order/stock values are rewritten and no additional live voucher is issued. Additional rules can be provisioned by owner-controlled maintenance; this release does not introduce a public issuance API or a separate voucher-management dashboard.

A selected reward reserves usage atomically with invoice creation; other invoices cannot consume the last usage slot. Backend payment confirmation redeems and increments usage exactly once. Existing unredeemed claims can be repriced on invoice edit, replaced, or released on unpaid cancellation. Unpaid invoices without proof expire after the existing seven-day policy; uploaded proofs retain their claims. First-order reservations block another first-order reward until resolved. Issued invoices retain their stored price for payment; later rule changes apply when editing/requoting, not silently while paying.

Shipping, payment methods/destinations, inventory mutations, order statuses and authentication remain governed by existing code. Analytics continues observing backend final totals. Preview-only fixtures cover percentage, fixed, minimum, cap, expiry, restrictions, multiple rewards, concurrency and tampering; no fixture voucher is created in production.
